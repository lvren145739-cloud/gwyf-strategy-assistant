# 0.3.0 验证记录

以下均为选定开发测试，不代表独立总体准确率。

- `v3-evaluation.json`：9 个固定输入比较中旧版 7、新版 8 个完全一致；剩余一例为故意错误选区，未凭空补齐不可见牌。
- 整帧自动找牌：5 个完整桌面均正确，4 个自动计算；另一例 5♣ 部分遮挡分数未达阈值，保留核对。扑克 0057 中当前五张为 A♦9♦5♣2♥K♠，排除后方 8♥ 弃牌。
- 17 个第三视频无牌场景：均未留下可采用牌面，自动计算次数为 0。仍不能据此保证所有背景不会误报。
- 3 个合成布局按用户照片中的 9♣8♣ / A♥ 配置，含浮动 17、左右倾斜：均完整识别并满足自动条件。未取得用户 5 张原图的本地像素文件，合成场景不能算原图实测。
- `automatic_flow.py`：默认无需框区、17 对 A 自动停牌、重复截图保持撤销和历史、缺牌停用旧建议、重复牌阻止自动采用、皇家同花顺自动计算、扑克不足五张保留草稿、归档撤销、420×341 紧凑同屏通过。
- `recognition-policy.test.js` / `state.test.js`：完整性、分数、牌背、重复牌、牌组/历史记录校验通过。
- `bridge-results.json`：实际 pywebview 扫描、注入脚本与 Python RPC，通过全部 9 个接口和错误恢复。
- `windows-native-results.json`：真实 Windows 3.14 嵌入式 Python、WebView2 Promise RPC、EnumWindows 和 MSS 自建窗口截图通过。首次完成的运行：https://github.com/lvren145739-cloud/gwyf-strategy-assistant/actions/runs/39413613979 。不是实际游戏测试，DPI、多屏、游戏焦点和全局快捷键不在此次证明范围。
- `python-compatibility.json`：标准 Python 3.11–3.15 在独立 Linux 环境实际加载当前四个模型、整帧识别、中文路径与 JSON 返回校验。Windows 各版本依赖锁见 windows-locks；真实原生 GUI 仅测嵌入式 3.14。
- 性能实测见 `benchmark.json`，整帧 CPU 识别包括候选定位、模型复核和预览生成；不含截屏和策略计算，不能当作 Windows 完整延迟。

106 个审核过的正例裁块含同一手牌的重复视角；765 个背景裁块含难负例。模型分数未校准，不能作为成功概率。未承诺所有 52 张牌、全部光照和视角均正确。

# 0.2验证记录

- 实际推理：标准CPython 3.11.17、3.12.14、3.13.5、3.14.8、3.15.0，独立Linux x64环境，均通过整帧识别、模型加载、NumPy/OpenCV、Python返回值JSON序列化、中文模型路径与版本筛选测试。去除耗时字段后输出摘要完全一致。
- Windows依赖：对3.11–3.15逐版本解析完整依赖，要求NumPy、OpenCV、pythonnet、clr_loader与cffi为wheel，全部通过。记录见windows-locks。
- 同输入模型对照：9个选定开发案例，旧版6例、新版7例整区完全一致。侧视三张 Q♥/10♠/10♣ 由全部错误变为全部正确。开发案例含训练重叠，不能视作准确率估计。
- 原错误选区保留：旧有一例选区切掉整张A，新版也不会凭空读取；另设相同完整选区供两版对比。错误裁切不是模型成功读取整手。
- 负例失败仍保留：第三视频的白鸭子可产生疑似牌形裁块；新版低分点数会留空并提示复核，尚不能保证所有非牌面都被定位器排除。
- 历史/策略：重复截图不增加已用牌，庄家后续牌归档、立即记录扑克弃牌、保留牌身份校验、撤销和保存还原通过。原样引擎与稳定仓库字节一致，概率与二十一点既有检查通过。
- 界面：浏览器中二十一点16对10与扑克皇家同花顺建议、归档撤销、模拟截图和确认、识别错误停用旧建议、主按钮同屏、小窗布局、独立预览通过。Chrome云策略禁止file://，预览通过本机HTTP验证。

没有Windows真机：原生全局快捷键、MSS窗口截图、WebView2、焦点、置顶、DPI和多显示器仍未实机验证；不能将Linux推理或模拟桥接描述为这些功能已验证。自由线程Python暂不支持。
